# Product Announcement

Introduces a new feature, product, or major update. Generates excitement and drives adoption.

## When to Send

- On launch day or during a launch window
- Consider a teaser email 1-2 days before for major launches

## Key Elements

- **What's new** — clear, jargon-free explanation
- **Why it matters** — the benefit to the user, not just the feature
- **Visual** — screenshot, GIF, or short video showing it in action
- **CTA** — try it now, learn more, watch the demo
- **Context** — if it was user-requested, mention that ("You asked, we built")

## Best Practices

- Lead with the benefit, not the feature name
- Show, don't just tell — visuals dramatically increase engagement
- Segment by relevance — don't announce enterprise features to free users
- Time it with in-app announcements for a cohesive experience
- Keep it focused — one announcement per email

## Common Mistakes

- Announcing multiple features in one email (dilutes impact)
- Too technical — reads like release notes, not a benefit-driven announcement
- No visual — hard to get excited about text describing a UI change
- Sending to users who can't access the feature (wrong plan, wrong region)
- No clear way to try the feature immediately
